# D WIKI — Next.js + Upstash Redis

Статьи и картинки хранятся в общей базе Redis. Стартовых статей нет.

## Vercel

Подключите **Upstash for Redis** в Storage / Marketplace к проекту D-WIKI.
Нужны серверные переменные `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (read/write).
Также поддерживаются `KV_REST_API_URL` и `KV_REST_API_TOKEN` от интеграции Vercel.
Не добавляйте префикс NEXT_PUBLIC: токен должен оставаться секретным.
После подключения выполните Redeploy. SQL и ручное создание таблиц не нужны.
Без Redis публикация недоступна: сайт сообщает об отсутствии настройки.

## Локальный запуск

Node.js 22+. `npm ci`, скопировать `.env.example` в `.env.local`, заполнить URL/токен, затем `npm run dev`.
Проверки: `npm test`, `npm run typecheck`, `npm run build`.

## Авторство

Сервер создаёт случайный токен в HttpOnly, SameSite=Lax cookie. В статье хранится только SHA-256 токена. Авторство и версия статьи проверяются сервером в атомарном Lua-скрипте вместе с уникальностью заглавия. Публичный ID автора не даёт права редактирования. Очистка cookie или смена браузера лишает доступа к редактированию; восстановления нет. Закладки и черновики остаются локальными.

## Изображения

JPG, PNG, GIF, WebP до 1 МБ, с проверкой сигнатуры. Файлы сохраняются в Redis блоками base64 по 64 КБ и выдаются через `/api/images/:id`. SVG запрещён. Большие изображения можно добавлять по внешней ссылке. Незавершённые загрузки истекают через час. Завершённые изображения хранятся без TTL; неиспользуемые загрузки автоматически не удаляются. Расходы Redis зависят от запросов и размера данных.

## Ограничения

Лимиты на автора: 60 сохранений и 30 загрузок в час. Это базовая защита, не полноценная антиспам-система. Лента загружает весь каталог; для большого количества статей потребуется серверная пагинация. Новые статьи других авторов видны после обновления страницы. Не включайте eviction для данных сайта; настройте резервные копии. Публикации старого локального деморежима автоматически не переносятся.

Интеграционные проверки требуют подключённой базы. REST API: https://upstash.com/docs/redis/features/restapi

## Модерация

Страница `/moder` защищена серверной проверкой пароля и случайной HttpOnly-сессией в Redis (8 часов). Вход ограничен 10 попытками в час на IP. Пароль не передаётся в клиентском коде: в серверном модуле хранится scrypt-хеш. Для смены пароля можно задать `MODERATOR_PASSWORD_HASH` в формате `salt:hex-scrypt-64-bytes`.

Модератор может редактировать чужие статьи, подтверждать их, снимать подтверждение и удалять. Любое редактирование сбрасывает подтверждение, автор статьи при редактировании модератором сохраняется. Старые статьи без статуса считаются неподтверждёнными. Удалённые статьи сохраняются на 30 дней в `dw:trash:<id>`; публичный список и индекс заглавий очищаются атомарно. Медиафайлы при удалении не стираются, поскольку могут использоваться другими статьями.
